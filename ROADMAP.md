# Waddle's Quest — Roadmap (Kanban)

A lightweight, version-controlled kanban board. Move a card between the columns
below as it progresses: **Backlog → Up Next → In Progress → Done**. Each card has
an effort tag and a one-line scope; deeper how-to lives in [AGENTS.md](AGENTS.md)
(the playbooks make most of these recipe-driven).

**Effort:** `S` ≈ a few hours · `M` ≈ a focused session · `L` ≈ multi-session · `XL` ≈ its own project.

> installed + authed). It's idempotent — add a card here, re-run, and only the new

- [x] **QA fix: SDK called pre-init + guest/account save leak (16 Jul 2026)** — two reported issues, one root cause. The store adapter's `cgData()` gated only on the SDK *global* existing (true the instant the `<script>` loads), so the import-time `load()` and every early `save()` called `data.getItem/setItem` before `SDK.init()` resolved — logging the reviewer's "CrazySDK is not initialized yet" error and silently failing into localStorage. And because writes mirrored to a **shared** localStorage key, progress leaked across identities: guest → login → logout carried the account's coins onto the guest. Fixes: (1) **`setCloudReady()` gate** — the Data Module is untouchable until main.js flips the flag after `portal.init()` succeeds; (2) **cloud-exclusive writes** — once live, saves go only to the per-identity Data-Module store (localStorage remains the no-SDK fallback + a one-time read migration when the identity's store is empty); (3) **auth listener** — `SDK.user.addAuthListener` detects login/logout (`_userId` compare) → `location.reload()` so the boot flow re-reads the right store (no-save-while-onRun means a mid-run reload just reverts to the pre-run save); (4) `loadingStart` now fires inside `init()` after the SDK can actually hear it. Verified: zero "not initialized" console errors on boot (previously dozens), post-init saves land in `SDK_DATA_local` with raw localStorage untouched, and a 777-coin save round-trips through the Data Module across a reload. Files: `meta.js`, `portal.js`, `main.js`.
